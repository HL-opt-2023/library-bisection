Find the library’s book

A stack contains 100 books, exactly one of which belongs to the library. The exit alarm sounds whenever a group you test contains that book. How can you identify it using as few tests as possible?

1. Click or drag to select books.2. Test the selected group.3. Use the result to plan your next test.

Red: alarm triggered. The library book is in the tested group.
Green: no alarm. The library book is outside the tested group.

Test the library book by itself to finish. Green tests fade excluded books; red tests do not automatically fade books outside your selection. The “still possible” counter records green-test eliminations, so keep track of what you infer from red results. “Restart” keeps the same target; “Default” chooses a new one.

After you play: the connection to bisection

Testing roughly half the remaining candidates at each step divides the search into two smaller possibilities. Starting with 100 books, repeated halving reduces the worst-case number of candidates as follows:

100 → 50 → 25 → 13 → 7 → 4 → 2 → 1

Seven balanced tests identify the book by inference in the worst case. This is optimal for identification when there is exactly one target, signals are accurate, and each group test has equal cost: seven yes/no answers can distinguish 128 possibilities, while six can distinguish only 64. The game may require an additional single-book test to confirm it. Numerical bisection uses the same halving principle on an interval bracketing a root. This can provide an entry point to step-size selection in gradient descent under the appropriate continuity and convexity assumptions.
